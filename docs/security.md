# Security and deployment boundaries

The platform applies baseline HTTP protections in the Express bootstrap. Every response receives `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, a strict cross-origin referrer policy, and a restrictive permissions policy. JSON and URL-encoded request bodies are bounded at 1 MB, and Express disables its powered-by banner.

Authentication abuse protection is intentionally scoped to security-sensitive challenge operations rather than applied as a blanket request counter. Phone OTP requests, OTP verification attempts, email verification, resend operations, and password-reset flows enforce challenge expiry, maximum attempts, resend windows, and provider-safe development behavior. The authentication service tests cover these limits. General read-only workout, history, and analytics queries do not share the OTP counter because they do not create verification challenges; a broader API quota can be added later at the edge or gateway layer without changing authentication semantics.

The application uses the tRPC adapter as the server-wide API boundary. Validated procedures return typed success values or throw typed `TRPCError` responses; protected procedures reject missing sessions and ownership mismatches before database writes. Feature-specific persistence helpers return defined empty states for missing profiles and orphaned scheduled records. The production build does not enable an in-process scheduler, and no scheduled callback is active in the unpublished checkpoint.

This project does not require a custom Dockerfile for the current deployment target. It is a Node.js application using the managed WebDev build and runtime contract; it does not need system binaries, a second language runtime, or a custom process supervisor. The CI workflow validates the same Node build, type check, formatting contract, and tests used locally. If a future feature requires binaries such as FFmpeg or Chromium, a custom Dockerfile must be introduced through the project’s custom-container workflow rather than added speculatively.
